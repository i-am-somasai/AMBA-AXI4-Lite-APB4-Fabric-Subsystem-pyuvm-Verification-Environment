| **DEC-004** | 2026-11-23 | AXI-Lite W-First Ordering on Multi-Slave Crossbar | In multi-slave AXI4-Lite crossbar without per-master write data buffering, slave routing for W channel is established by address decoding `AWADDR`. Slaves cannot assert `WREADY` before receiving write routing. Driving `AWVALID` concurrently or with slight stagger allows crossbar to route both channels without requiring complex multi-entry store-and-forward data FIFOs. | Orchestrator |
| **DEC-005** | 2026-11-24 | Verification Architecture Deviation on Spec Item V-01 | Implement `AxilMasterAgent` as a full `pyuvm.uvm_agent` (with `uvm_driver`, `uvm_sequencer`, and passive `uvm_component` monitor), while implementing slave responders (RAM, APB bridge, peripherals) as cocotb coroutine models rather than full pyuvm agent classes. | Spec item V-01 specified "pyuvm environment with 2 AXI-Lite master agents + AXI-Lite slave responder agents + APB responder agent". In cocotb, slave responders reactively service incoming bus handshakes on clock edges. Structuring slave responders as cocotb reactive models rather than heavyweight UVM sequencer-driver hierarchies reduces abstraction overhead and improves simulation throughput while maintaining protocol fidelity. | Orchestrator |
| **DEC-006** | 2026-11-25 | CSR Formal `CHECK_CAUSALITY` Split Between `bmc` and `prove` | Run `axil_csr.sby` `bmc` (depth 20) with `-DFORMAL_CAUSALITY` (`CHECK_CAUSALITY=1`), and `prove` (k-induction) with `CHECK_CAUSALITY=0`. | `axil_props.v` tracks channel handshakes with 8-bit wrapping counters (`f_aw_handshakes`, `f_b_handshakes`, etc.). In unbounded k-induction, arbitrary initial counter states (including wraparound `f_b=255, f_aw=0`) violate `f_b <= f_aw`, and Yosys does not resolve downward hierarchical references (`u_axil_props.f_*`) for an inductive invariant in `axil_csr.v`. | **DEC-008** | 2026-11-25 | CDC Bridge Independent Domain Reset Behavior (`CD-03`) | Define expected behavior for `axil_cdc_bridge` when one domain resets mid-transaction: (1) If `rst_sys_n` asserts while `rst_slow_n=1`, the AXI4-Lite slave interface resets immediately to `ST_IDLE` (dropping any in-flight `clk_sys` transaction per AXI reset rules) and cross-domain reset synchronizers flush both async FIFOs and `slow_regs`; (2) If `rst_slow_n` asserts while `rst_sys_n=1`, slow-domain logic and both FIFOs reset while the active `clk_sys` FSM completes any already-accepted in-flight AXI transaction with `SLVERR` (`2'b10`, `rdata=0`) and waits for synchronized FIFO reset release before accepting new requests, guaranteeing the AXI master never hangs. | Prevents `ST_WAIT_RESP` deadlock and async FIFO Gray-pointer desynchronization when only one clock domain is reset mid-transaction, without adding any new ports to `axil_cdc_bridge` (preserving `docs/interfaces.md`). | R2-A |
